# HF 众包复核：答案恢复 + 分档交付

数据源 `taryya/RunningBench`（HF，public），10 个题包共 1,526 题。
最后同步 2026-09-15。

## 背景：为什么需要恢复

题包**不含标准答案**，而验收方式是"由回收方用标准答案合并计算一致率"。
那批答案随造包的机器一起丢了：`5hk3xk6dxy`（H100 aws_5，2026-08-26 起，
**2026-09-09 13:48 FAILED 结束**）。`copy_artifacts`、`logs` 均为空，ssh 主机名已无法解析，
它留下的唯一东西是 09-09 11:36 的代码备份 `backups/task_runtime_code_5hk3xk6dxy_20260909`
（180 文件），全文搜 `RBMA` / `bundle_0` / `review_id` 均无命中 —— 备份只覆盖代码，不含数据。

题包用了一套新的 `review_id`，与恢复树里任何语料交集为 0（11,802 题全量 / 5,971 题校验包 /
8,026 题 curated segments）。**但题目本身是旧的**，只是重新分配了 id。

## 答案怎么来的

| 来源 | 题数 | 方法 |
|---|---|---|
| `matched_question+option_text` | 1,241 | 题干原文检索 → 比对选项文本集合完全一致 → 按选项文本把旧答案字母重映射到题包字母 |
| `derived_unverified` | 257 | `rbma273` 源（273 题）本地无任何痕迹，用 Gemini 独立重判补出**候选**答案 |
| 无 | 28 | 12 题选项被改写过不敢用；15 题模型三票钉不住；1 题重试后仍无结论 |

题包渲染用 `Object.keys(options).sort()`，不打乱顺序，字母空间确定。
恢复出的 1,241 题，答案个数与 `n_select` 全部相符。

### derived_unverified 的可信度 —— 不要当 gold 用

用 gate ⑤ 那套"独立作答"：不出示候选答案、每票重排字母、按选项文本比对、三票取二、
钉不住则标 unstable 不产出。模型 `gemini-3.1-pro-preview`，与 CAPTION_MODEL 一致。

拿人工判定做外部校准（174 对），**exact 仅 39.7%**。更要命的是：

```
模型三票全一致  n=137  exact 39.4%
模型有分歧(2/3) n= 37  exact 40.5%   ← 反而略高
```

**模型的自信完全不预测正确性。** 整套语料的 caption、出题、闸门全程 Gemini 3.x，
现在又用同族模型判答案，三票一致反映的是自我一致（同样的偏置重复三遍），
不是答案被画面钉住了。因此 `unstable` 这个标记也只筛掉了模型自己摇摆的题，
筛不出模型稳定地答错的题。

绕开这一点的办法是**换一个非 Gemini 家族的模型重判、取交集**，尚未做。

## 最重要的一个数字

**标准答案指定为正确的选项中，27.1%（769/2836）被人工逐项核对时明确标为"✗ 画面否定"。**

不是"人没看到"，是"人看了，画面里是反的"。三条独立证据指向同一结论 ——
这些题是照着文字描述生成的、从未对着画面核验：

- 人工复核中 20.8% 的题找不到足够多被支持的选项（偏差几乎全为负）
- 模型的视觉回看闸门在已闸门三层淘汰了约 40%（1,335 → 792）
- 上述 27.1% 的逐项否定率
