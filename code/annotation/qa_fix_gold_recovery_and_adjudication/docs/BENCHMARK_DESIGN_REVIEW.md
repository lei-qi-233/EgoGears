# RunningBench：现有题目分布与设计现状

写给要对这套基准的**设计**提改进意见的读者。所有数字截至 2026-09-15，来自语料文件本身，
不是从历史文档转抄的。读完应当能回答："这套题该怎么重新设计。"

**统计口径**：`videobench` 那 1,892 题已排除。它们的 `video` 字段为 `null`、`span_sec` 为
`[null, null]`，无法定位到录像的哪一段，因此做不了任何基于画面的核验。本文其余部分不再提它。

---

## 1. 底层素材

第一人称户外导航录像（走路 / 跑步），不是第三人称人体动作视频。两个来源必须保持为独立的域，
不能合并后随机切分。

| 来源 | 内容 | 关键性质 |
|---|---|---|
| Google Drive 受控集 | 3 参与者 × 3 路线 × 3 运动条件（FastWalk/SlowWalk/Running）× 2 光照（Day/Night）= 54 段完整因子网格 | 同一路线被反复走过，随机切分会造成严重场景泄漏 |
| HuggingFace 集 | 3 贡献者（Alec / Markus / Mikail），共 210 段 | 无数据卡、无声明许可；路径拼接不安全（部分媒体在 `Alec/Alec/...` 而元数据在 `Alec/...`） |

语料实际覆盖 **148 段录像**，每段题数中位 76（最少 4，最多 221）。

**已知的混淆因子**（设计时必须处理，不是可选项）：

- P01 有音频、P02 无、P03 有 → **音频存在与否是完美的参与者捷径**
- P01/P02 经过重编码，P03 保留相机元数据且曝光/色彩/视场角明显不同 → **参与者与拍摄设备完全混淆**
- 昼夜与速度变体走的是同一批路线 → 随机切片或随机分视频都会泄漏
- 运动模糊、镜头抖动、低光噪声、广角畸变是**数据的固有属性**，不是要清洗的损坏

## 2. 题目分布（9,910 题）

### 2.1 按层

| 层 | 题数 | 占比 | 单位 | 生成依据 |
|---|---:|---:|---|---|
| `segments_60s` | 8,033 | 81.1% | 60 秒片段 | **由 60 秒 caption 文本生成，从未看过画面** |
| `whole_video` | 1,411 | 14.2% | 整段录像 | 整片 360p/10fps 全局 pass + 180 秒窗口时间索引 |
| `cross_video` | 347 | 3.5% | 同一路线的多段录像 | 该路线所有录像的标注合并生成 |
| `excerpts` | 119 | 1.2% | 时长受控的摘录 | 同 whole_video 流程 |

**分布严重失衡**：81% 的题集中在唯一一个"没看过画面就出出来"的层。

### 2.2 形式参数

```
provenance:  google_drive 5256 · huggingface 4654
arity:       single 5804 (58.6%) · multi 4106 (41.4%)
选项数:      6 项 5634 · 8 项 3282 · 4 项 447 · 5 项 309 · 7 项 237 · 3 项 1
答案个数:    1 项 5804 · 3 项 1763 · 2 项 1249 · 4 项 1010 · 5 项 81 · 6 项 1 · 7 项 2
```

选项数不统一（3–8）直接影响可猜率的可比性：2 选项题的随机基线就是 50%，
汇总数字若不按选项数拆开会得出错误结论。

### 2.3 题型

**`segments_60s`（8,033）—— 只有 3 个宽泛类别，粒度过粗：**

```
visual-grounded-qa          3422  42.6%
spatial-temporal-reasoning  2978  37.1%
trajectory-qa               1631  20.3%
```

**`whole_video`（1,411）—— 7 类，围绕整条路线的结构：**

```
landmark-order 337 · event-phase 272 · multi-step-turns 240 · environment-stages 171
route-summary 146 · landmark-revisit 138 · start-end-relation 107
```

**`cross_video`（347）—— 11 类，最贵也最脆：**

```
unique-transient-obstacle 71 · landmark-visibility-comparison 55 · route-phase-alignment 49
reverse-view-recognition 37 · description-matching 28 · divergence-point 24
different-start-shared-path 24 · route-retrieval 20 · landmark-order-discrimination 16
route-divergence-location 14 · same-route-identification 9
```

### 2.4 证据时间戳（`evidence_spans`）

| 层 | 有 span | 含义 |
|---|---|---|
| `whole_video` | 1411 / 1411 | 可按引用证据精确切片做视觉核验 |
| `excerpts` | 119 / 119 | 同上 |
| **`segments_60s`** | **0 / 8033** | **只能整段 60 秒送检，核验粒度更粗，判定与其它层不严格可比** |
| **`cross_video`** | **0 / 347** | 同上 |

这不是记录疏漏，而是生成方式的必然结果：`segments_60s` 是照着文字写的，本来就没有"引用了哪几秒"。

### 2.5 描述（captions，1,795 条）

```
segments_60s              1400   60 秒密集描述
fullvideo_structural       125   整片结构标注（阶段/转弯/环境）
windows_180s               130*  180 秒描述（*其中 130 条是由 60 秒聚合而来，未看视频）
windows_180s（真看视频）     97
whole_video_aggregated      24   未看视频，由下层聚合
whole_video                 19   整片描述
```

聚合而来的描述（154 条）不应与真看视频写的描述等同使用。

## 3. 质量闸门与实测结果

### 3.1 五道闸门（`build_fullvideo_annotations.py`）

```
结构检查 · 泄漏黑名单 · 题干时间戳 · 长度线索 · 高清视觉回看(480p) · 盲猜×3 · 确定性选项洗牌
```

只有 `whole_video` / `cross_video` / `excerpts`（合计 1,877 题）跑过全部闸门。

| 层 | 总数 | 通过 | 盲猜淘汰 | 视觉回看判"与证据矛盾" | 证据不足 |
|---|---:|---:|---:|---:|---:|
| whole_video | 1411 | 592 | 407 | 377 | 35 |
| cross_video | 347 | 135 | 103 | 81 | 28 |
| excerpts | 119 | 65 | 32 | 21 | 1 |
| **合计** | **1877** | **792 (42.2%)** | 542 | 479 | 64 |

**盲猜活下来的 1,335 题里，视觉回看只过了 792 题（59.3%）。** 也就是说，即便题目不能被盲猜，
仍有 40% 的标注答案与画面对不上。

### 3.2 盲猜率：一个必须纠正的历史错误

项目内曾用 **17.6% 的"恒答上限"**（永远选同一个字母能得多少分）当作盲猜率汇报。
**实测盲猜率是 48.6%**，差近 3 倍。这两个是完全不同的量。

设计新基准时：验收指标必须写明是"实测盲猜率（不给视频，三票取二）"，不能用恒答上限代替。

### 3.3 干扰项修复：v1 失败的原因是设计，不是执行

对 432 道单选做配对实验（同题、同模型，原版与修复版各测一次）：

| 阶段 | 盲猜可答 | 95% CI |
|---|---:|---|
| 原版（对照组） | 95.4% | [93.0, 97.0] |
| v1 修复后 | 73.4% | [69.0, 77.3] |
| v1 + v2 串联 | **33.1%** | [28.8, 37.7] |

**为什么必须有对照组**：修复对象是"因为被猜中才入选"的题，只测修复后一次会把回归均值算作修复的功劳。
实测对照组是 95.4% 而非 100%，那 16 个百分点就是回归均值。

**v1 卡在 73% 是设计缺陷**：

> 要求"干扰项必须被证据否定" ⟹ 只能写画面里没有的东西 ⟹ 那些东西**先验上也更不常见**
> ⟹ 正确答案自动成为选项里唯一"像真的"那个。

```
Q: 路两侧紧邻什么？
   灰砾石 / 铁栏杆 / 高灌木 / **绿草** / 砖墙 / 沙土
```

每个干扰项都规规矩矩被证据否定了，答案依然一眼可见——草就是路边最平常的东西。

**v2 的两处改动**（在 v1 失败的 304 题上救回 161 题，53.0%，CI[47.3, 58.5]）：

1. **先验似真性对齐**：要求每个干扰项是"没看过视频的人会觉得至少同样可能"的东西。
   原则是**常见但不在场**，而非不常见且不在场。
2. **对抗迭代**：每轮改完立刻盲测，若仍被猜中，把模型的实际选择回传给改写者要求针对性重写，最多 3 轮。
   轮数分布：1 轮成功 88、2 轮 34、**3 轮 182**。只做一轮会丢掉后面 216 题。

**另一条**：v1 无条件重写，把 432 道单选里本来合格的 13 道改坏了。正确做法是分级——
先盲测原版，过了就原样保留；没过才进 v1；v1 没救回才进 v2；全失败则**退回原版**并标记，
绝不保留一个"唯一证据是它被尝试过"的重写。

### 3.4 `segments_60s` 的盲猜闸门结果（8,026 / 8,033 已判定）

```
passed 6,770 (84.4%) · still_guessable 1,256

来源构成: 本来就猜不中 3,887 · v1 修好 1,333 · v2 修好 1,550 · 修不好 1,256
按 arity:  单选 3,639/4,671 = 77.9% 通过 · 多选 3,131/3,355 = 93.3% 通过
```

单选明显更难修。这推翻了项目原有的 `--multi-only` 修复策略——**该修的是单选，不是多选**。

**注意**：这 6,770 题只过了盲猜闸门，**从未过视觉回看**（需要源视频，当时不在本地）。
参考 3.1 的 59.3%，它们的真实可用率大概率远低于 84.4%。

## 4. 人工复核的独立证据

对其中 1,526 题做了众包人工复核（10 包分发，每包约 150 题）。剔除一份经两套独立参照系
判定不可用的提交后，**1,071 条判定可与标准答案比对**。

```
人工自评:  clear 799 · ambiguous 196 · cant_tell 76
与标准答案完全一致:  50.5%     （验收线是 90%）
```

**三个指向同一结论的数字：**

| 证据 | 数值 |
|---|---|
| 标准答案指定为正确的选项，被人工逐项核对判为「✗ 画面明确否定」 | **23.2%**（577/2,487） |
| 人工找不到足够多被支持选项的题（偏差几乎全为负） | **21.3%**（228/1,071） |
| 模型视觉回看在已闸门三层的淘汰率 | **40.7%**（1,335 → 792） |

人和模型在**各自独立地**指出同一件事：这些题是照着文字描述生成的，从未对着画面核验。

标注员备注里反复出现的是「选项里写的东西画面里根本没有」：

> 「B：没有转弯 / D：没有转弯 / E：没有进入草地 / F：左侧没有集装箱 / **G：没有喷泉，那个是洒水器**」
> 「E 没有右转而是掉头」
> 「往返线路，很多物品出现了两次，无法判断何为先」

### 4.1 一个必须知道的方法论发现

同一批题、同一批标准答案，两个评判者：

| 评判者 | 与标准答案 exact 一致 |
|---|---:|
| Gemini（与出题同族模型） | **79.3%** |
| 人工 | **50.5%** |

**29 个百分点的差距。** 标准答案是 Gemini 出的题，判定的也是 Gemini —— 它与标准答案共享同一套盲点。
**任何同族模型的自评都会虚高约 30 个点。** 用同族模型验收等于没验收。

更细的一条：在与**同源标准答案**比对时，模型三票一致组 90.9% vs 有分歧组 56.4%（相差 34.5 点）；
但在与**人工**比对时，三票一致组 39.4% vs 有分歧组 40.5%（无差别）。
即：模型的自洽性能预测"是否与同源答案吻合"，**不能**预测"是否与人的观察吻合"。

## 5. 已被实测否决的题型（不要重新引入）

| 题型 | 可用率 | 否决理由 |
|---|---|---|
| `same-route-identification` | 1/9 | 问的是**整片级全称命题**（"是不是同一条路线"），任何一组 ≤60 秒窗口都判不了。回看器总能在被引用证据之外找到一个岔路或匹配，于是把正确答案判成 contradicted |
| `route-retrieval` | 2/20 | 同上（"哪些视频包含这个序列"） |

替代方案（同样的能力，但答案能从窗口本身判定）：问两段视频在**哪里**分岔、问一对地标是**什么顺序**。

**其它已知陷阱：**

- **往返路线**：去程的左 = 回程的右。凡顺序题和左右题必须点明是去程还是回程，
  且所有 evidence span 必须落在 `turnaround_sec` 的同一侧，否则题目本身有歧义。
  人工复核里 `spatial-consistency` 有 33.7% 凑不够被支持选项，这是主因之一。
- **干扰项必须来自本视频自己的素材**（重排、左右镜像、挪到错误的 phase、配错地标）。
  同路线的兄弟录像只能提供本视频确实没有的地标；`route-summary` / `environment-stages` /
  `start-end-relation` 三类**绝不能**用兄弟录像的真实描述当干扰项——同一条路线，兄弟的描述在这儿通常也是真的。
- **绝不引入标注里根本不存在的环境或物体**（海滩、高速、森林、室内跑道、桥、木栈道）。

## 7. 交给设计评审的具体问题

1. **层级失衡**：81% 的题在一个"没看过画面就生成"的层。是补做视觉核验，还是整层重做？
   若重做，`segments_60s` 应不应该继续存在，还是并入带 evidence span 的整片线？

2. **`evidence_spans` 缺失**：8,380 题（segments + cross_video）没有证据时间戳，
   导致视觉核验只能整段送检，判定与其它层不可比。是否应把"生成时必须产出 evidence span"
   设为硬约束——即**禁止从纯文本生成题目**？

3. **验收闭环的循环性**：出题、写描述、闸门、判定全程同一模型家族，自评虚高约 30 个点。
   验收环节是否必须强制换模型家族，或强制人工抽样？抽多少？

4. **无法计算标注者间一致性**：当前分包设计中任意两包零重叠，没有一道题被两个人做过。
   识别出一份不可用的提交纯属事后补救（靠"恰好有旧标准答案"和"恰好跑了模型重判"两个间接参照系）。
   锚点题比例定多少？10%？15%？

5. **选项数不统一（3–8）**：可猜率无法跨题型直接比较。是否统一为固定选项数？

6. **单选比多选更难修**（77.9% vs 93.3% 通过盲猜闸门），但多选的验收又更难判。
   arity 该怎么配比？

7. **域混淆**：参与者与拍摄设备完全混淆，音频是完美的参与者捷径，昼夜/速度变体共用路线。
   分组策略最低应按 `(participant, route_index)`；若要严格的未见场景评测，需按 route_index
   跨所有参与者和条件整体留出。这个约束是否应写进 schema 强制执行？

8. **发布前的隐私处理**：需剥离容器元数据、去除或粗化 GPS、审查人脸与车牌，
   并对音频做统一决策（要么全部去除，要么定义成显式的视听任务并说明缺失音频的处理策略）。
   HF 集当前无数据卡、无声明许可。
