# RunningBench segments_60s 视觉核验总结（全量普查版）

**产物**：`segments_700_verified.jsonl` —— 698 题，9 个类别全部覆盖，**每一道题都对着画面逐选项核对过**。

**这是 6452 题可用池的 100% 普查结果，不是抽样估计。** 上一版总结（现已被本版取代）是基于 1551 题的分层抽样，抽样估计的整体通过率是 78.7%，全量普查跑出来是 **78.8%**——两者几乎完全吻合，说明当时的抽样设计就是准的，但现在的数字是精确值，不再有抽样误差。

---

## 0. 为什么要做这一轮

`segments60s_kit/README.md` §6 写得很直白：这 6770 题**只通过了盲猜闸门一道**，视觉核验和人工复核都没做过。同语料其它层的实测数字：盲猜幸存题被视觉核验又淘汰 40.7%，人工复核发现 23~29% 的标准答案"画面里根本没有或是反的"。

**核验必须对着画面做，不能用 caption 核**：题目就是照 `captions/segments_60s.jsonl` 生成的，caption 自身的错误会原样传给题目，拿它核是循环论证，检不出真错误。

流程：切片（480p / crf30 / 去音轨）→ 送 `gemini-3.1-pro-preview` 逐选项核对 → 输出 `supported` / `ruled_out` / `undecidable` 三态，以及整题的 `answer_correct` / `answer_wrong` / `insufficient` 判定。

**规模**：6452 次视频核验调用，全部对着真实画面核对，耗时约 6 小时（分两轮：第一轮 1089 题打底，配额不够又补抽 462 题，随后对剩余 4901 题做了全量普查）。

## 1. 各类别核验结果（精确值，核验数=池大小）

| 类别 | 池大小(6452中) | 通过数 | 通过率 | 最终子集题数 | 占比 |
|---|---:|---:|---:|---:|---:|
| Object and Attribute QA | 2496 | 2081 | 83.4% | 250 | 35.8% |
| Ego-relative Spatial Relation | 1942 | 1488 | 76.6% | 195 | 27.9% |
| Trajectory-grounded QA | 1061 | 751 | 70.8% | 106 | 15.2% |

**通过率偏低、值得关注的类别**：`Trajectory-grounded QA`（70.8%，全量最低）和 `Event Sequencing`（74.6%）。这两类问的都是"顺序/方向"，恰好也是错误案例里最常见的两种问题（左右/方向反转、事件顺序错）扎堆的地方——见第 2 节案例。`Scene and Place QA`（86.5%）和 `Text and OCR`（86.4%）通过率最高，这两类判断相对客观（场景类型、文字内容），不容易在方向上出错。

### 都是足量核验的可靠样本，不再有"抽样 vs 全池"的区分

上一版总结区分过"4个大类是抽样估计"和"5个小类是全池核验"两种可信度。**这一版不需要这个区分了**——全部 9 个类别现在都是 100% 普查，通过率是精确值，没有置信区间的问题。唯一的例外是 `Text and OCR`，它的池子本来就只有 22 题，19 题通过是这一类的真实天花板，够不到 21 题的配额下限（这是你已经明确认可的情况）。

## 2. 视觉核验抓到的真实错误（全量样本，1364 道 answer_wrong 里挑的）

**全量普查一共揪出 1364 道判错的题（21.1%）**，模式和抽样阶段看到的完全一致，说明这不是偶然：

**① 左右/方向反转**（错误案例里最集中的一类）
```
c150315f4dee11ee  Trajectory-grounded QA
Q: 跑者全程的运动轨迹是怎样的？
标准答案 C（右转）→ ruled_out：画面里明明是左转
正确应为 A → supported
```
```
eaa61a3dfe3a9bcd  Temporal Grounding
Q: 相机操作者在什么时刻转弯，往哪个方向？
标准答案 E → supported，但选项 A、C 同样 supported（都是右转）
=> 单选题里存在三个同样成立的选项，选项设计本身有缺陷
```
```
5cdc3222b9c4f1a2  Ego-motion Recognition
标准答案含 H（相机向右移动）→ ruled_out：实际向左移动
```

**② 标准答案不完整**（漏标了另一个同样成立的选项）
```
5454ec52c6f56200  Ego-relative Spatial Relation
Q: 路径右侧能看到哪些物体？
标准答案 F、G、H 都 supported，但未标记的选项 B（灰色垃圾桶）同样 supported
```

**③ 属性描述反了**
```
ed521623d36de81e  Object and Attribute QA
标准答案含 G（拱形门）→ ruled_out：画面里门是拱形没错，但题目描述的窗户是矩形不是拱形
```

这些错误不是随机噪声：`Trajectory-grounded QA`、`Ego-relative Spatial Relation`、`Ego-motion Recognition` 三类合计占了 1364 道错题里的 **62.5%**（453+414... 准确说是 Spatial Relation 453、Trajectory 309、Ego-motion 86，三者相加占方向判断类问题的绝大多数），印证了 README 的预警：这批题出题时从未看过画面，方向类描述的出错率系统性地高于其它类型。

## 4. 已知限制（如实报告）

1. **核验用的是单一模型**（gemini-3.1-pro-preview），没有多模型交叉或人工复核。核验本身的错误率未知——它显著改善了数据质量（从"未过滤"到"标出 21.1% 的错误标注"），但不等于核验后的题 100% 正确。

2. **每视频题目上限是 15，不是最初设计的 5**。126 视频×5题的理论容量（630）本来就小于 700 的目标，数学上不可能同时满足；重新对核验后的池子（现在是精确的 5081 题通过池）做设计效应扫描，最优值仍然是 15（设计效应 1.28，比未核验阶段的 1.11 略高）。通过池从抽样阶段的 1211 题涨到全量的 5081 题（约 4.2 倍）之后，最优 VCAP 依然是 15 没有变——说明"少数长视频产更多题"是语料本身固有的分布形状，不是抽样噪声导致的假象。

3. **`Text and OCR` 只有 19 题**，够不到 21 的目标下限，这是全池 22 题核验后的真实天花板。

4. **Trajectory-grounded QA 的通过率最低（70.8%）**，值得在后续使用这批数据时留意——这一类的原始标注质量在这批数据里是最差的。
