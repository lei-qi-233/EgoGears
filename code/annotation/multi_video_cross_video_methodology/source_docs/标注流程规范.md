# RunningBench 标注流程规范

**给谁看**：拿到 Google Drive 那 54 段录像、负责做标注的人。

**目标**：产出**必须看视频才能答对**的题目。这是唯一的验收标准 ——
一道不看视频也能猜对的题，无论文字多漂亮，价值是零（甚至是负的，因为它会让评测分数虚高）。

## 1. 你拿到的是什么

### 1.1 录像清单

```
54 段录像 · 12.77 小时 · 单段中位 15 分钟（范围 10-20 分钟）
```

采集设计非常规整，**3 参与者 × 3 速度 × 2 光照 × 3 轨迹**：

| 参与者 | 段数 | 时长 | 速度 × 光照 | 轨迹 |
|---|---|---|---|---|
| P01 | 18 | 4.33 h | SlowWalk / FastWalk / Running × Day / Night | Traj01 / 02 / 03 |
| P02 | 18 | 4.30 h | 同上 | Trial01 / 02 / 03（命名不同） |
| P03 | 18 | 4.14 h | 同上 | Traj01 / 02 / 03 |

**同一条轨迹会有 6 个版本**（3 速度 × 2 光照）。这是这批数据最有价值的地方 ——
同一条路在不同速度、不同光照下走一遍，可以问「这两段录像是不是同一条路」。

### 1.2 文件命名怎么读

```
P03_FastWalk_Night_Traj02_Trial01.mp4
 │      │       │      │       └── 第几次尝试
 │      │       │      └────────── 轨迹编号（P02 用 Trial 而非 Traj）
 │      │       └───────────────── 光照：Day / Night
 │      └───────────────────────── 速度：SlowWalk / FastWalk / Running
 └──────────────────────────────── 参与者：P01 / P02 / P03
```

> ⚠️ **文件名里的信息绝对不能写进题干或选项。**
> 写了就等于把答案告诉答题者 —— 题干出现「fast」「running」「Traj」「.mp4」一律作废。
> 详见 §8 第 1 条。

### 1.3 元数据（每段录像都有）

```json
{
 "run_id": "P01_FastWalk_Day_Traj01",
 "scene_id": "scene_kit_campus",      全部 54 段都在同一个场景
 "route_id": "route_01",              route_01 / 02 / 03，各 18 段
 "duration_sec": 1002.07,
 "direction": "A_to_B",
 "shape": "out_and_back",             路线形状
 "out_and_back": true,
 "turnaround_sec": 501,               折返时刻（秒）
 "speed": "FastWalk",
 "lighting": "Day",
 "confidence": "medium"               ⚠️ 见下
}
```

**关于 `confidence`：54 段全部是 `medium` / `medium-low` / `low`，没有一段是 high。**

```
medium      18 段
medium-low  18 段
low         18 段
```

而且 P02 那 18 段的 `shape` 是 `out_and_back_unconfirmed`（未确认折返）。

**所以：`turnaround_sec` 和 `shape` 只能当参考，不能当真值。**
如果你要出「是否返回起点」类题目，**必须自己看视频确认折返点**，
不要直接信这个字段。你确认后的结果请记录下来（见 §7），这本身就是有价值的产出。

## 2. 视频怎么切片

三种粒度，各有用途。**切片纯本地操作，不需要联网。**

### 2.1 60 秒片段（主力）

整段录像**从头到尾平铺切完，不抽样**：

```bash
# 第 N 片：起点 = N × 60 秒
ffmpeg -y -ss $((N*60)) -i 输入.mp4 -t 60 \
  -vf scale=-2:480 -c:v libx264 -preset veryfast -crf 30 \
  -an -movflags +faststart 输出_segment_${N}.mp4
```

- 一段 15 分钟的录像 → 15 片
- **最后一片会不足 60 秒**（余料），这是正常的
- `-an` 去掉音轨（音频不参与标注）

> ⚠️ **不足 10 秒的尾料不要出题。**
> 现有语料里有 3 个片段只有 1.3 秒，却各自出了 6 道题 ——
> 1.3 秒（约 38 帧）几乎是一张静止图，出不了需要看视频的题。
> 这类片段只写 caption，题目栏留空。

### 2.2 180 秒窗口（时序题用）

```bash
ffmpeg -y -ss $((N*180)) -i 输入.mp4 -t 180 \
  -vf scale=-2:480 -c:v libx264 -preset veryfast \
  -b:v 450k -maxrate 585k -bufsize 900k \
  -an -movflags +faststart 输出_w${N}.mp4
```

**为什么 180 秒要用码率封顶而不是 crf**：180 秒 × crf30 会到 12-18 MB，
超过模型内联上限（11 MB）。450 kbps 刚好塞得下。

**180 秒窗口有真实的时间结构** —— 有多个阶段、有转弯，
所以能问「顺序」「变化」「先后」，这是 60 秒片段问不出来的。

### 2.3 任意时长：把 60 秒片段组合起来

60 秒片段是最小单位，**把连续的若干片拼起来就得到任意时长的视频**。
这样不用重新采集就能覆盖多种时长，能问的题也随之变多。

#### 实测：时长直接决定能出什么题

| 时长 | 出题成功率 | 95% 置信区间 | 能问什么 |
|---|---|---|---|
| 1 分钟 | 42% | [27, 58] | 只有一个阶段、几乎无转弯 → 只能问「画面里有什么」 |
| 2 分钟 | 53% | [37, 69] | 开始有转弯和阶段切换 → 能问顺序 |
| 4 分钟 | 60% | [42, 75] | 多阶段、多转弯 → 能问变化、趋势 |
| 7 分钟 | 60% | [42, 75] | 同上 |

> ⚠️ 四个区间互相重叠，**所以不能说「时长越长越好」有多少个百分点的优势** ——
> 每档只有 30 来道题，分辨不出 20 个百分点以内的差异。
> 能确定的是方向：**1 分钟明显吃亏，2 分钟以上明显好转。**

**结论：主力做 2-4 分钟档（2-4 片拼接），1 分钟档少做。**

#### 两种「组合」，用途完全不同

**① 连续拼接 → 得到一段更长的自然视频**

```bash
# 要 0-180 秒，直接从源视频切，不要拼接已编码的片段
ffmpeg -y -ss 0 -i 输入.mp4 -t 180   -vf scale=-2:480 -c:v libx264 -preset veryfast   -b:v 450k -maxrate 585k -bufsize 900k -an -movflags +faststart 输出.mp4
```

> ⚠️ **从源视频重切，不要把已编码的 mp4 拼起来。**
> 拼接会在接缝处留下编码痕迹，而且答题者可能把接缝当成「场景切换」误判。

用途：问顺序、问变化、问转弯序列、问环境趋势。

**② 非连续片段 → 分别给出，不要拼成一个文件**

比如想问「第 2 片和第 9 片是不是同一条路的两段」，
应该**给两个独立的片段文件**，题干里用「片段 A」「片段 B」指代。

> ⚠️ **绝对不要把非连续片段拼成一个视频。**
> 拼出来的东西在现实中不存在（一个人不会瞬间从一处跳到另一处），
> 答题者会被接缝误导，题目也失去意义。

用途：问「是否同一地点」「哪些地标重复出现」「两段的环境差异」。

#### 建议的时长配比

一段 15 分钟的录像（15 片）建议这样切：

```
2 分钟档   （2 片）   6 个   ← 主力
4 分钟档   （4 片）   3 个   ← 主力
7 分钟档   （7 片）   2 个
整段       （15 片）  1 个   ← 问全局路线结构
1 分钟档   （1 片）   按需   ← 只在片段内容特别丰富时做
```

同一段视频的不同时长档**可以重叠**（比如 0-120s 和 0-240s 都做），
这不是浪费 —— 同一段素材在不同时长下能问的题不一样。

#### 预测题：一个免费的真值来源

**这是时长组合最有价值的用法。**

给答题者看 **0-120 秒**，问 **120-180 秒**会发生什么 ——
真值就在视频里，不需要额外标注。

```
输入给答题者:  0-120 秒的片段
问:            接下来一分钟会向哪边转弯？会看到什么？环境如何变化？
真值:          120-180 秒的片段（你看，但不给答题者看）
```

**但预测题有一个特有的陷阱，必须避开：**

| 可以问 ✅ | 不能问 ❌ |
|---|---|
| 前方路径可见地向右弯 → 会右转 | 会不会有车经过 |
| 折返路线 → 会反向重看已见地标 | 会不会有人挥手 |
| 正进入建筑密集区 → 环境会更城市化 | 会不会下雨 |
| 上坡趋势 → 配速会降 | 手机会不会响 |

> **真值存在 ≠ 题目公平。** 问「120-180 秒会不会有行人出现」，
> 答案客观存在，但那是抛硬币，不是理解力测试。
> **只问那些「看了前 120 秒就应该能推出来」的事。**

**自检方法**：出完预测题后，自己只看 0-120 秒试着答一遍。
如果你看了也答不出，那这题不公平，废掉。

折返类题目最适合做预测题 —— `out_and_back` 的录像在折返点之后
会反向重看前半程的地标，**答案由已看到的内容唯一决定**，
而不看前半程则完全无从得知。折返点中位在 435 秒，
所以「看 0-400 秒，问 450-500 秒」这种跨折返点的题最干净。

### 2.4 整段录像

不切，直接用。用于问「整条路线的形状」「是否返回起点」这类全局问题。

超过 15 分钟的录像可能太大，可以降到 288p：

```bash
ffmpeg -y -i 输入.mp4 -vf scale=-2:288 -r 8 \
  -c:v libx264 -preset veryfast -crf 32 -an 输出_288p.mp4
```

### 2.5 分辨率怎么选（有过教训）

| 用途 | 分辨率 | 理由 |
|---|---|---|
| 看整体结构（顺序、阶段、转弯） | 288p / 8fps | 够用，文件小 |
| **核实细节（复核答案对不对）** | **480p** | **不能更低** |

> ⚠️ 曾用 360p 做复核，把一块**清晰可读的路牌**误判成「模糊」，
> 于是把一道正确的题判成了错的。**复核用的清晰度必须高于写描述时用的清晰度。**

## 3. Caption（描述）怎么写

每个片段写一份结构化描述，**五个字段**。这是出题的原料，写得越具体，题目越难猜。

### 3.1 五字段结构

```json
{
  "overall_environment":     "整体环境：什么地方、什么时间、天气、光照",
  "objects_and_attributes":  [{"category": "...", "description": "..."}],
  "actions_and_events":      ["按时间顺序发生了什么", "..."],
  "trajectory_and_turnings": {"trajectory_type": "...", "description": "..."},
  "spatial_relations":       {"left_side": "...", "right_side": "...", "path": "..."}
}
```

### 3.2 真实范例（`P01_FastWalk_Day_Traj01` 第 0 片，0-60 秒）

**overall_environment**
> 白天一条安静的林荫街道，可能位于住宅区或机构园区内。环境因茂密成熟的树冠而略显昏暗或大面积遮荫，因此路灯是开着的，投下温暖的黄色人工光，与自然日光混合。

**objects_and_attributes**
```json
{"category": "Pedestrians", "description": "前方一名行人，戴蓝色渔夫帽、白色长袖衫、深色长裤（可能是牛仔裤），背黑色背包。"}
{"category": "Infrastructure", "description": "铺装沥青街道为主路，右侧有铺装人行道。两侧有高杆路灯，亮黄灯。左侧有一根红白条纹警示柱。"}
{"category": "Structures", "description": "左侧有木质构筑物/围挡和一个深色（黑或深蓝）大型垃圾箱。右侧有一栋浅色墙面、大玻璃窗的建筑。"}
```

**actions_and_events**（按时间顺序）
```
"镜头沿铺装道路中央平稳直行，跟随一名同向行走的行人。"
"行人逐渐从道路中央移向右侧。"
"镜头在视频末段追上并从行人左侧超过。"
```

**trajectory_and_turnings**
```json
{"trajectory_type": "straight",
 "description": "镜头全程沿街道笔直向前，没有任何左转、右转或环形转弯。"}
```

**spatial_relations**
```json
{"left_side": "木质构筑物/围挡、大型深色垃圾箱、红白条纹警示柱、通往更远处停车区的草地与树木。",
 "right_side": "铺装人行道、低矮灌木、草地、以及一栋浅色墙面配大玻璃窗的建筑。",
 "path": "中央为铺装沥青街道，两侧有路灯和树冠。"}
```

### 3.3 写 caption 的三条要求

**① 写具体的、可核实的东西。**
「一名行人」不如「一名戴蓝色渔夫帽、背黑色背包的行人」。
具体的细节才能出难题；笼统的描述只能出「这是室内还是室外」这种废题。

**② `actions_and_events` 必须按时间顺序。**
这是所有时序题的基础。如果你愿意标时间范围（`"00:20 - 00:45"`）更好，
但**出排序题时要把时间戳藏起来**（见 §8 第 5 条）。

**③ 只写你看见的。** 不要推断、不要补全。
「路可能通往停车场」→ 不要写，除非画面里能看到。
描述里的每一句话，后面都可能被用来判定一道题的对错。

## 4. 题目怎么出

### 4.1 格式：一律 8 选项、3 个正确

**这不是风格偏好，是实测结论：**

| 格式 | 不看视频猜对的比例 |
|---|---|
| 6 选项单选 | **64.7%** ❌ |
| 8 选项多选（选 3） | **25.3%** |
| 8 选项多选（经过严格干扰项规则） | **7.3%** ✅ |

单选题有两个叠加漏洞（下节详述），修一个还剩一个。**所以直接用多选，不做单选。**

题干里要写明「以下有三项正确」。

### 4.2 每个片段出几道题？

**由内容决定，不设指标。**

现有语料的最大教训就在这里：它规定「每片必须出 6 道」，
结果 1.3 秒的片段也交了 6 道题 —— 那 6 道必然全是凑的。

参考区间：

| 片段情况 | 建议题数 |
|---|---|
| 内容丰富的 60 秒（有转弯、有事件、有多个物体） | 2-4 道 |
| 平淡的 60 秒（一路直行、没什么东西） | 0-1 道 |
| 不足 10 秒的尾料 | **0 道** |
| 180 秒窗口 | 3-5 道 |

**宁可少出，不要凑数。** 一道好题的价值高于十道可猜的题。

### 4.3 问什么

好题的判据只有一个：**答题者必须看视频才能答对。**

| 类型 | 例子 | 为什么需要看视频 |
|---|---|---|
| 顺序 | 三个地标出现的先后顺序 | 单帧看不出顺序 |
| 变化 | 从开头到结尾环境如何变化 | 需要对比两端 |
| 转弯序列 | 依次做了哪几个转弯，方向和幅度 | 必须跟踪整段轨迹 |
| 重复经过 | 哪些地标出现了不止一次 | 需要识别折返/环线 |
| 跨录像 | 这两段录像是不是同一条路 | 必须对比两段 |
| 空间关系 | 某物在路的哪一侧、相对什么位置 | 需要看画面 |

**不要问这些：**

| 别问 | 为什么 |
|---|---|
| 这是室内还是室外？ | 常识可答 |
| 拍摄者是在走还是在开车？ | 常识可答 |
| 天空是什么颜色？ | 单帧可答，且答案通常唯一 |
| 会不会有行人出现？ | 不可预测，答案是抛硬币 |

## 5. 干扰项怎么造 —— 全流程最难的一步

**这一节请反复读。** 现有语料 48.6% 的题不看视频就能答对，**全部败在这一步。**

### 5.1 核心原则

> **一个错误选项的「错」，必须只能通过看视频才能发现。**

不是「它是错的」就够了 —— 而是「不看视频无法判断它错」。

### 5.2 反例（这是现有语料里的真实题目）

```
Q: 以下哪项描述了镜头的轨迹及其与行人的互动？
   A. 镜头在路口右转以跟随该行人。
   B. 当行人移向道路右侧时，镜头完全停止。
   C. 镜头在岔路口急左转以避开该行人。
   D. 镜头向后退离该行人，行人朝镜头走来。
   E. 镜头平稳直行，最终追上并从行人左侧超过。      ← 正确答案
   F. 镜头跟随行人环绕一栋建筑做环形运动。
```

**这道题不用看视频就能答对，有两个原因：**

**① 正确项是最长、最具体的那个。**
A-D、F 都是短句、笼统；E 有「平稳」「追上」「左侧超过」三个细节。
**实测：策略「挑最长的选项」在单选题上命中率 42.2%。**

**② 干扰项在常识上不可能。**
「镜头向后退」「环绕建筑做环形运动」—— 一个人正常向前走的第一人称录像里
不会出现这些。答题者只要知道「这是有人在走路」就能排除。

### 5.3 正确做法：四条硬规则

**规则 1 · 用这个片段自己的东西造干扰项。**

不要引入画面里没有的东西。看反例里的「环形运动」「向后退」——
这些都不在这个片段的内容范围内。

✅ 该这么造：这个片段里有「行人」「垃圾箱」「警示柱」「路灯」「建筑」，
干扰项就在这些东西之间做错误组合。

**规则 2 · 靠「组合错」，不靠「内容错」。**

| 造法 | 例子 |
|---|---|
| 顺序颠倒 | 先超过行人，再看到垃圾箱（实际相反） |
| 左右互换 | 垃圾箱在右侧（实际在左侧） |
| 位置错配 | 警示柱在人行道上（实际在街道左侧） |
| 幅度写错 | 轻微右偏（实际笔直无偏） |
| 主体调换 | 行人超过了镜头（实际是镜头超过行人） |

**规则 3 · 不要让每个干扰项都只改一处。**

这条最反直觉，但极其重要。假设正确答案是「浅黄色·多层·大玻璃窗」，
你造了这五个干扰项，每个只改一处：

```
A. 深灰色   · 多层 · 大玻璃      ← 只改颜色
B. 浅黄色   · 多层 · 大玻璃      ← 正确答案
C. 浅黄色   · 单层 · 大玻璃      ← 只改层数
D. 深红色   · 多层 · 大玻璃      ← 只改颜色
E. 浅黄色   · 多层 · 小窄木窗    ← 只改窗户
F. 浅黄色   · 多层 · 极小窗      ← 只改窗户
```

**看出问题了吗？** 颜色栏「浅黄色」出现 4 次、层数栏「多层」出现 5 次、
窗户栏「大玻璃」出现 4 次 —— **正确答案就是每一栏里出现最多的那个值。**
答题者逐栏投票就能还原答案，完全不用看视频。

> 这个坑我们真踩过：按「每个干扰项只改一处」的规则重造了一批题，
> 盲猜率**从 48.6% 升到 75%**，比原来更糟。

**正确做法**：多数干扰项**同时改两处以上**，且改的组合各不相同。
让任何一栏都不存在压倒性多数。

**规则 4 · 八个选项长度和详细程度要接近。**

正确的三项**不能是最长的三项**。写完后数一下字数，差距控制在 ±25% 以内。

### 5.4 造完自己验一遍

**盖住答案，只看八个选项，问自己：**

> 如果我没看过这个视频，只知道「这是有人在户外走路的第一人称录像」，
> 我能排除掉几个选项？

**能排除任何一个，那个选项就要重造。** 理想状态是八个看起来都同样可能。

## 6. 自检四关

每道题出完后**依次**走这四关。**顺序不能变**，理由见下。

### 第一关 · 打乱选项

把八个选项**随机打乱**，正确答案不要固定在某几个位置。

> ⚠️ **必须先打乱，再做第二关。**
> 出题时习惯把正确答案写在前面，答题者也习惯选前面的 ——
> 不打乱就测，会测出一个虚高的数字（我们曾误读为 56.6%，其实是位置造成的假象）。

### 第二关 · 盲猜测试（最重要）

**盖住视频，只看题干和八个选项，答三遍。**

- 三遍里**答对两遍以上** → **这道题作废**，回到 §5 重造干扰项
- 三遍答案不一致、且都不对 → 通过

**找别人做这一关效果最好** —— 自己出的题自己盲猜，会不自觉带入记忆。
如果只能自己做，出完题隔一天再测。

### 第三关 · 看视频复核

**用 480p 片段**（不要更低），对着画面逐项检查：

- 标记为正确的三项，画面是否**真的**支持？
- 标记为错误的五项，画面是否**真的**否定？

三种结果：

| 结果 | 处理 |
|---|---|
| 画面支持标记的答案 | ✅ 通过 |
| 画面显示的是别的 | ❌ 改答案或废题，**并记录画面实际是什么** |
| 画面看不清、判不了 | ❌ 废题 |

### 第四关 · 答案分布检查（每批做一次，不是每题）

一批题做完后，统计**正确答案的分布**：

- 某个位置（比如 B、D、F）出现得特别多？→ 打乱不够随机
- 某类答案内容反复出现（比如一半的转弯题答案都是「继续直行」）？
  → **这一整类题要重新设计**，因为答题者靠常识就能蒙对

> 这一关抓的是第二关抓不到的东西。盲猜的人可能不知道
> 「走路视频大多数时间在直行」，但真正的答题模型知道。

## 7. 交付格式

### 7.1 目录结构

```
你的交付/
├── captions/
│   ├── segments_60s.jsonl
│   ├── windows_180s.jsonl
│   └── whole_video.jsonl

│   ├── segments_60s.jsonl

```

**JSONL 格式：一行一条记录**，不是一个大 JSON 数组。

```json

 "video": "P01_FastWalk_Day_Traj01",

   "overall_environment": "...",
   "objects_and_attributes": [{"category": "...", "description": "..."}],
   "actions_and_events": ["...", "..."],
   "trajectory_and_turnings": {"trajectory_type": "...", "description": "..."},
   "spatial_relations": {"left_side": "...", "right_side": "...", "path": "..."}
 }}
```

### 7.3 题目记录

```json
{"id": "P01_FastWalk_Day_Traj01_seg0_q0",
 "video": "P01_FastWalk_Day_Traj01",
 "segment_index": 0,
 "span_sec": [0, 60],
 "question": "题干（写明有三项正确）",
 "options": {"A": "...", "B": "...", "C": "...", "D": "...",
             "E": "...", "F": "...", "G": "...", "H": "..."},
 "answer": ["B", "E", "G"],
 "option_order": "shuffled",
 "question_type": "顺序 / 变化 / 转弯序列 / 重复经过 / 空间关系 / 跨录像",
 "evidence_sec": [[12, 20], [45, 52]],
 "why_hard": "答题者必须跟踪什么才能答对",

 "checks": {
   "shuffled": true,
   "blind_test": {"attempts": [["A","C","F"], ["B","D","G"], ["A","E","H"]],
                  "hits_of_3": 0},
   "visual_recheck": {"verdict": "supported", "notes": ""},
   "annotator": "谁做的自检"
 }}
```

**`checks` 字段必填。** 没有自检记录的题无法验收 ——

## 8. 已知踩坑清单

每一条都是实际发生过的，附后果。

| # | 坑 | 后果 | 怎么避 |
|---|---|---|---|
| 1 | 题干或选项出现文件名信息 | 「fast」「running」「Traj」「.mp4」直接泄漏采集条件 | 出题前搜一遍这些词 |
| 2 | 正确项写得比干扰项更长更具体 | 「挑最长的」单选命中 42.2% | 八项长度差 ±25% 内 |
| 3 | 干扰项在常识上不可能 | 知道「有人在走路」就能排除 | 只用本片段有的东西造 |
| 4 | 每个干扰项只改一处 | 正确答案变成逐栏众数，盲猜率升到 **75%** | 多数改两处以上，组合各异 |
| 5 | 出排序题时 caption 里带时间戳 | 顺序直接印在输入里，题目作废 | 出排序题前藏掉时间戳 |
| 6 | 打乱之前做盲猜测试 | 测出虚高假象（曾误读 56.6%） | 先打乱，再盲猜 |
| 7 | 复核用低分辨率 | 360p 把清晰路牌判成「模糊」，废掉正确的题 | 复核固定 480p |
| 8 | 给每个片段规定固定题数 | 1.3 秒的片段也交 6 道题，全是凑的 | 题数由内容决定 |
| 9 | 只看代理指标不做盲猜 | 「正确项最长」这个指标修好了（48%→28%），盲猜率反而升了 | 代理指标不能替代盲猜实测 |
| 10 | 用小样本下结论 | 30 道题分辨不出 20 个百分点的差异 | 每类题至少 100 道再看比例 |
| 11 | 直接信 `turnaround_sec` | 54 段置信度全部 medium 及以下，P02 全部未确认 | 自己看视频确认并记录 |
| 12 | 不足 10 秒的尾料也出题 | 1.3 秒约 38 帧，等于静止图 | 只写 caption，不出题 |

## 9. 验收标准

一批题交付时，我们会这样验：

```
1. 随机抽 10% 做独立盲猜 → 可猜率必须低于 15%
2. 随机抽 10% 看视频复核 → 答案正确率必须高于 90%
3. 检查 checks 字段完整性 → 缺失即退回
4. 检查答案位置分布 → 均匀，无某位置占比过高
5. 检查同类题答案内容分布 → 无某答案压倒性多数
```

**第 1 条是硬门槛。** 现有语料是 48.6%，我们要的是 15% 以下。

有疑问随时问，特别是遇到「这道题算不算可猜」的边界情况 ——
判断标准是：**你能想出一个不看视频的理由来选它吗？** 能，就是可猜。
